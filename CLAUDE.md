# mapyourmind development handoff

mapyourmind is an offline macOS flowchart and mind-map app. It grew out of Excalidravv 1.28 and ports the interaction-quality program in `MAPYOURMIND-INTERACTION-QUALITY-PRD.md` onto that codebase. Read README.md and the top of COMPATIBILITY-CHECKLIST.md first; the checklist records which PRD releases are done and the decisions that override the PRD.

## Architecture

Native Swift AppKit and WKWebView, with classic JavaScript scripts sharing globals. No npm runtime, backend, account or analytics. The one server is opt-in browser mode (`--serve`, `src/serve.swift`), bound to 127.0.0.1, so a meeting that allows only tab sharing can show the app. It rewrites `index.html` to load `web/browser-bridge.js`, which replaces `window.webkit.messageHandlers.native`: storage actions go to the same `LocalStore` over HTTP, and clipboard, PNG, import and links use browser APIs. It checks Host, Origin and a per-launch token. The app and `--serve` each hold an `flock` on `<library>/.lock`, so they never write to one library together. `--serve --ui-test` uses a temporary library. Rough.js and all fonts are bundled. `web/index.html` defines script order. Frontend JavaScript must stay compatible with the macOS WebKit runtime.

- `web/model.js`: graph operations, layout, selection, clipboard, undo and graph validation.
- `web/app.js`: canvas interaction, rendering, inspectors, editing, native bridge and PNG export.
- `web/rich-text.js`: UTF-16 text marks and shared editor/canvas text layout.
- `web/commands.js`: ⌘K command search, contextual to the selection.
- `web/features.js`, `web/notes.js`: context actions, collapsible branches, comments, images, stickers and attached placeholders.
- `web/import-format.js`, `web/import.js`: bounded versioned mind-map import contract and interface.
- `web/navigation.js`: document sidebar and switching with save completion.
- `web/document-format.js`, `web/notebook.js`: Notes documents, sanitization, editing and PDF layout.
- `src/serve.swift`: browser mode HTTP server.
- `web/browser-bridge.js`: browser stand-in for the native bridge, loaded only by browser mode.
- `src/main.swift`: native shell, persistence, import picker, clipboard, bounded PDF rendering, native tests and shutdown flush.
- `Info.plist`: application version and identity. `build.sh` compiles, signs and runs the native storage test.

## Persistence and compatibility

mapyourmind is a separate app from Excalidravv: bundle ID `app.mapyourmind.mac`, data in `~/Library/Application Support/mapyourmind/`. On first launch, if that folder does not exist and an Excalidravv library (`~/Library/Application Support/Local Flowchart/`) does, `LocalStore` takes a one-time copy of it. The Excalidravv folder is only ever read. App replacement does not replace saved user documents. Never edit live user data for tests. Native test mode uses a temporary store and restores the clipboard.

The current store writes schema 3 and reads schemas 1 and 2. Schema 3 keeps each image once as `images/<sha256>.png` and image nodes carry `imageRef`; `load` inflates refs back into `imageData` (keeping `imageRef`), the page strips `imageRef` into its `imageRefs` map, and `persist` sends refs only, uploading an image with `putImage` the first time it is seen. So the editor, undo, clipboard and export only ever see `imageData`. `collectImages` removes files referenced by neither `documents.json` nor `recovery.json`, once per launch only, because mid-session an uploaded image may wait for the save that refers to it. Excalidravv builds before 1.28 reject schema 3 as a newer version and never overwrite it. Future schema versions must be rejected without overwriting data. Both JavaScript and native validation must remain compatible. `M.clone` is a structural clone that deliberately shares `imageData` strings rather than copying them, and `M.same` compares two snapshots without serialising them; both exist because documents carry base64 images and every edit, undo step and save takes a snapshot. Never replace either with a JSON round trip. Writes are atomic with `recovery.json` retaining the previous valid snapshot. `LocalStore.save` validates the received object with `valid(object:)`, then moves the primary file to recovery with `rename(2)` only while `primaryStamp` (size and modification date from the last load or save) still matches; otherwise it rereads and validates the file as before. Keep the storage test that writes an invalid primary behind the store's back. The old mapyourmind 1.4 build supports only schema 1; never point it at this library.

Defaults for new elements live in `preferences.json`, apart from the documents, loaded before anything is drawn and passed through `M.setDefaults`, which drops anything its per-key rules refuse, so preferences can never make a document invalid. `M.node` applies them to fresh flowchart and mind-map shapes, `M.connect` to non-tree connectors, and `M.extend` only for the step after a terminator: a flowchart Start / end, a mind-map pill, or a mind-map root still in the default root shape; that step takes the After Start / end shape, its fill and its default size. Everything else Tab and Enter create inherits every visual property from the source, including size and uniform text formatting (PRD Release B), which is the lesson of the transparent default reverted in 1.20.0. `web/defaults.js` owns the inspector button and the ⌘, panel.

Layout direction is a property of a tree's source node, resolved by `M.treeDirection`, which walks to the root and falls back to the document's `direction` so older diagrams are untouched. `layout` reads it per root, never once for the canvas, and every other reader (tree connector sides, collapsed badges, reparent hints, drop previews) must resolve it the same way. There is no page-wide direction control.

Mind-map parentage is defined by `node.parent` and tree edges. Manual links do not alter parentage. Branch moves reorder and realign descendants; roots move freely. Hidden collapsed descendants remain saved and copied. Use visible graph filtering for rendering, hit testing and exports. Clipboard branches detach parents outside the copied graph, while retaining internal parentage and attached placeholders.

## User interface

English, monochrome, Google Sans interface and comments, Excalifont diagram text by default. Notes and diagram text also support Google Sans and Comic Shanns. Preserve font license files. Google Sans ships as WOFF2 subsets made with the command in `GOOGLE-SANS-NOTICE.md`; subset again from the original TTFs listed in `google-sans-sources.json` (also in git history) rather than from the WOFF2 files. Mind-map roots default to pastel-purple pills; `M.extend` gives the node after any pill (flowchart Start / end or mind-map root) a white rectangle, while Enter on a root still makes a pill root. Circle is an optional inspector and shape-picker choice.

Circles keep equal dimensions during creation, editing and resizing. Text is wrapped inside a padded square within the circular outline. `circleTextInset`, `textWrapWidth`, and `fitCircle` must stay consistent with rich text rendering and the edit overlay. All eight resize handles resize the diameter; text determines the minimum size. Cardinal and legacy diagonal connector anchors lie on the outline. Hit testing excludes bounding-box corners.

The document sidebar, not a home screen, is the way between documents: the application opens the last edited document and `#home` survives only as the empty state. `web/navigation.js` owns sorting, manual order, drag-to-reorder, the Trash section, the context menu and resizing. Documents sort by `created` descending until every one carries a finite `order`, which `normalizeDocumentOrder` writes for the whole list at once; partial orders have no single correct reading. Reordering and resizing use pointer capture only when `e.isTrusted`, so synthetic test events still work. The sidebar width lives on `state.sidebarWidth` and drives the `--sidebar-width` custom property that both the panel and `#stage` read.

An optional `bend` point on a connector takes over the middle of its route; `edgeGeometry` returns it so hit testing, label placement and export all follow the same polyline without knowing about it. Straight connectors ignore a bend. A selected connector draws handles at `edgeGeometry` p and q, never a halo along `pts`, which used to disagree with straight and curved lines. Dragging a handle is the `endpoint` drag type, which reattaches the live connector on every move from `drag.origin`, hides that connector only while its end is loose, and so never puts two arrows on screen; it it outranks shapes in hit testing, refuses the connector's own other end, and skips tree connectors. `hoverPortsNode` is the single gate for helper arrows: none during a connect or endpoint drag, and none while any connector is selected.

Every connector stops `connectorGap` (8px) short of both shapes along its first and last segment. `trimEnds` moves only the two ends of a route planned from the outline anchors, so `edgeGeometry` p and q are the drawn ends and hit testing, labels, handles and export all follow them; `anchor` still returns the outline point. The arrowhead is not part of the Rough.js path: `arrowHead` and `drawArrowHead` paint a filled, slightly rounded triangle about four stroke widths long (at most half the last segment) in the stroke colour, crisp at every sloppiness, and the sketched line stops at its base. Connector lines use round caps and joins.

An empty editor holds a zero-width character, not just a `<br>`: WebKit paints no caret for a selection anchored at an element boundary, and a snapshot cannot see a contenteditable caret, so this cannot be verified from a test. The character is stripped in `plainEditorText` and `readRichEditor`. The text editor is a transparent overlay with no border: editing a node must change nothing on screen but the caret, so the canvas skips that node's text and its selection frame while the field is open. Its side padding is derived from `textWrapWidth`, never from a repeated per-shape inset, or the field and the canvas wrap at different widths. Only `.label-editor` carries an outline, because a connector label has no shape behind it.

While a connector label is being edited the canvas keeps its clipped gap but draws no text there: the transparent field carries the only copy, which is what keeps an empty label from covering its own line.

Colour palettes scroll horizontally and must keep at least the selection ring's reach as padding, or the ring clips. The custom colour lives in `.palette-row` beside the scroller, never inside it, so scrolling cannot hide it.

Rectangles carry an `edges` style of `sharp` or `round`; no other shape does, and Start / end remains a separate full stadium. Sloppiness was checked against the reference in FEEDBACK.md and deliberately left unchanged.

New shapes carry `sloppiness: 1`; leaving it unset falls back to the pre-1.5 legacy sketch, which is rougher than any level the inspector offers. New shapes start white; free text is the only transparent kind, mind-map roots keep pastel purple and the Note shape keeps `M.noteFill`. The transparent default tried in 1.12.0 was reverted in 1.20.0 because nodes created with Tab inherit it and whole flowcharts came out unfilled. Note draws as a filled body plus an unfilled folded corner, so `sketchShape` may return an array and every caller must handle both. `fillStyle` (`hachure`, `cross-hatch`, `solid`) is an inherited node style whose fill weight and hachure gap track the stroke width; the inspector shows it only once a fill colour is set. The inspector is 240px wide and ordered fill, highlight, stroke, text; the canvas gutters in `fit` and `ensureVisible` track that width. Font size and fill style use the shared choice-group builder, which stacks any group of more than three options under its label.

Connector labels are stored on the connector as `label`, `labelMarks`, `fontFamily`, `fontSize` and `textColor`; there is no label node. `edgeLabel` builds a live view over the edge so the shared rich-text editor, formatting, inspector and PNG renderer work unchanged, and `clipAroundLabel` clips the stroke around the text instead of filling a rectangle over it. Labels sit at `labelT` along the arc length of the drawn path, centred when it is absent and clamped clear of both shapes while dragging. They take priority over connector ports when hit testing, and disappear when their text is emptied. Keep JavaScript and native label validation in step.

Text, font and shape changes on a flowchart shape go through `reflow`, which keeps its centre so Tab and Enter chains, placed on the source's centre line by `M.extend`, stay straight; handle resizing calls `autoSize` directly and keeps the dragged edge. ⌘1 to ⌘6 follow the order of `shapeLabels`, and ⌘⇧0 is 100% zoom.

Preserve four connector ports and eight square resize handles, with resize precedence. Two or more selected elements share one box from `M.bounds` carrying those same handles; `resizeGroup` scales them all by one pair of factors clamped by the most constrained element, and each element then normalises itself exactly as it does when resized alone. Ports draw as blue arrows pointing away from the shape, 13 screen pixels out, and the active side fills in; this replaced the four round points and the 28 pixel offset agreed in September. The style panel is docked to the stage's right edge at full height with square corners, so any later rule must not restore a `max-height` or a floating radius. Comments open from their clickable badge or context menu, not ordinary node selection. Enter sends comments and replies; Shift Enter creates a newline; composing input must not submit. Tree connectors use restrained curves; manual links remain independent. Notes-specific shortcuts must not invoke diagram actions.

## Build and verification

Rendering must not look nodes up linearly per connector or per frame: use `M.byId`, whose index relies on node and edge arrays only ever being appended to or replaced, never spliced or assigned by index. `richLines` caches measured lines per element id, keyed by text, marks, font, size and wrap width; anything else that changes line breaking must join that key. Pan, zoom and note scroll set `positionMoved` instead of calling `changed()`, and `flushSave` writes only when an edit or a moved position is waiting. `zsh build.sh` then `--ui-test --perf-test` prints timings on a 2,096-node document; run it before and after a change that touches paint, hit testing, layout or saving.

Run the commands in README.md. Pick the suites a change can reach rather than sweeping every time: `node --test` for anything in `web/model.js` (under a second), `--ui-test` for canvas, connector, selection, resize, label and export behaviour, `--feedback-test` for inspector controls and rich text, `--navigation-test` for the document sidebar and stickers, `--notebook-test` for Notes. The integration suite is the only slow one at four seconds, and a build is twelve. Sweep all of them once before packaging or installing, never after every edit.

A UI test drives a real window on a real desktop, so it opts out of two behaviours that are correct in use but arrive from outside the test: the native `windowDidResignKey` save, skipped under `--ui-test`, and the `blur` handler that rolls back a drag, skipped when `window.uiTest` is set. Losing key focus mid-run was the cause of a long-standing intermittent failure; it committed the open edit through `flushSave` and reverted the drag in progress. Each suite also swallows trusted pointer events. Do not remove either guard, and do not let production read `window.uiTest` for anything else. Native suites cover integration, feedback, navigation and notebook behavior. For movement/resize, test pointer-up, subsequent layout, undo and native persistence, not pointer-move alone. `autoSize` reports the height text needs and may only grow a shape during a resize, never shrink it; typing is the one thing that resizes freely. Shapes and connectors share one stacking order through `paintOrder`, which both the canvas and PNG export must use, or layer order cannot put a shape behind a connector. PNG uses the same seeded shape/text rendering as the canvas, and defaults to a white background so an image matches the board; transparent stays a deliberate choice in the export dialog.

`build.sh` builds Apple Silicon only, with an explicit `arm64-apple-macosx13.0` target. Never use the compiler's host OS target for distribution: it silently raises the minimum macOS to the build machine's version. macOS 13 has not been tested directly. Builds remain ad hoc signed, without Apple notarization or automatic updates.

Every native test run must pass `--ui-test` (or be `--storage-test`); any other launch opens the real library. To share a build, zip it with `ditto -c -k --sequesterRsrc --keepParent dist/mapyourmind.app mapyourmind-<version>-AppleSilicon.zip` and attach it to a GitHub release. To install locally, quit the running app normally and wait for its shutdown save, replace it with the verified build, then reopen. Never force-kill it or run two instances against the same store.
