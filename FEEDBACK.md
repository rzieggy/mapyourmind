| F14 | 2026-10-06 | Mind map / layout | Mind maps lay out in columns: every node at the same depth starts at the same x, so the column is as wide as its widest node and short nodes get long connectors and wasted space (see Zieggy's own "Risk Question" map). Zieggy prefers Whimsical: no columns. | **Constant connector length**: each child starts a fixed gap after **its own parent's** right edge (vertical maps: below its parent's bottom), so branches are as compact as their text. Node width stays flexible: it fits the text and wraps only past a maximum, as today. Consider raising that maximum closer to Whimsical's (its long nodes wrap at roughly 45 characters; ours is 320px text / 360px roots, about 28 characters). | Cause: `layout` in `web/model.js` builds `columns[depth]` from the widest node per depth (`levels`/`sizes`) and places every child at `columns[depth + 1]`. Change: in `place`, set `c.x = n.x + n.w + gap` (horizontal) / `c.y = n.y + n.h + gap (+ placeholder space)` (vertical), drop the per-depth columns; the cross-axis stacking (up/down extents, placeholders, only child on the parent line) stays. Layout is not stored per node, so **existing maps will reflow the next time they are edited**; confirm with Zieggy that this is wanted (likely yes). Check reparent drop previews, collapse badges and tree-connector sides still line up, and the mind-map tests that assume columns. The max width lives in `fitWidth` in `web/app.js`. |

Update CLAUDE.md. Test: outline present while editing a text child, absent after commit and in PNG/PDF export. |
